# مرصد الإنجازات

**مرصد الإنجازات** منصة عربية RTL لإدارة العمل التربوي وبناء ذاكرة مؤسسية للمعلم الأول ورئيس المجال. تجمع أعمال القسم والمعلمين والطلبات والوثائق والتخطيط والتحصيل والإشراف والاجتماعات والفعاليات في سجلات مترابطة قابلة للمتابعة بدل توزيعها بين ملفات ومجلدات منفصلة.

> الإصدار الجاري: **v0.12.0 — دورة التدخل وقياس الأثر**
> آخر نقطة استقرار خضراء قبل هذا الإصدار: **v0.11.0**
> المعاينة الحية: **https://physicsbasit-debug.github.io/marsad-alinjazat/**

## الفكرة

التطبيق ليس مخزن ملفات فقط. البيانات التشغيلية والعلاقات وحالات المتابعة تحفظ داخل التطبيق، بينما يمكن استخدام **Google Drive** كمخزن فعلي للملفات عند تفعيل الربط. بهذه البنية يمكن معرفة: ماذا طُلب، من المسؤول، ما الذي أُنجز، ما الذي تأخر، وما الأدلة المرتبطة به.

## الوحدات الحالية

- **لوحة القيادة:** الأعمال التي تحتاج انتباهًا، جدول الأسبوع، مؤشرات التنفيذ، وآخر النشاطات.
- **المعلمون:** ملف مهني وسيرة ذاتية، مؤهلات وخبرات ودورات وإنجازات، وربط الطلبات والوثائق والزيارات.
- **التخطيط ومتابعة المنهج:** خطط المادة والصف، الوحدات، نسب الإنجاز، المسؤوليات، واكتشاف التأخير.
- **التحصيل والنتائج:** تسجيل التقويمات والاختبارات، المتوسط ونسب الإتقان، فئات المتابعة، والتدخلات العلاجية والإثرائية المرتبطة بالنتيجة.
- **الإشراف الفني والزيارات:** الزيارات، جوانب القوة والتطوير، التوصيات، وإجراءات المتابعة.
- **طلبات الملفات:** طلب ملف من معلم، رابط رفع خارجي، صندوق مراجعة، اعتماد وأرشفة.
- **الاجتماعات والقرارات:** محاضر الاجتماعات، الحضور، القرارات، المسؤولون، المواعيد وحالات التنفيذ.
- **الفعاليات والتوثيق:** سجل فعالية، المشاركون، الصور والأدلة، الغلاف، والجاهزية للتقرير.
- **الوثائق:** فهرسة الملفات المستلمة وربطها بسياقها التربوي.
- **التقارير الرسمية:** عقد تقرير موحد يبني تقارير القسم والمعلم والتخطيط والتحصيل والإشراف والاجتماعات والفعاليات من السجلات الفعلية، مع معاينة ونسخة A4 قابلة للطباعة.
- **الأرشيف التاريخي:** عرض سنوي للقراءة فقط يجمع السجلات حسب العام الدراسي، ويكتشف السنوات تلقائيًا، ويُنتج حزمة تسليم قابلة للطباعة دون نسخ البيانات إلى مخزن موازٍ.
- **البحث الشامل:** بحث عربي موحد من رأس التطبيق في المعلمين والخطط والتحصيل والإشراف والطلبات والاجتماعات والفعاليات والوثائق، مع فلاتر للقسم والعام الدراسي وتنقل مباشر إلى السجل الأصلي.

## دورة التدخل وقياس الأثر في v0.12.0

يوسع هذا الإصدار التدخلات العلاجية والإثرائية الموجودة أصلًا داخل **التحصيل والنتائج** بدل إنشاء قسم موازٍ. لكل إجراء يمكن تسجيل مقياس أثر منظم يتضمن اسم المؤشر، الوحدة، اتجاه التحسن، خط الأساس، الهدف المسجل، النتيجة الفعلية، تاريخ القياس، ومصدر الهدف أو المعيار.

الحكم الناتج **حسابي فقط** نسبة إلى الهدف المسجل: لم يُقَس، حقق الهدف، تحسن ولم يبلغ الهدف، لم يحدث تغير، أو تراجع. لا يعرّف المرصد حد إتقان أو تصنيفًا تربويًا من تلقاء نفسه.

### حارس المرجع العُماني

- السجل الجديد لا يقترح قيمة افتراضية لحد التصنيف/الإتقان في الواجهة.
- حفظ تقويم جديد أو تعديله يتطلب توثيق **مصدر الحد المستخدم** وسنة/إصدار المرجع وملاحظته عند الحاجة.
- قياس أثر رقمي يتطلب توثيق مصدر الهدف أو المعيار؛ يمكن أن يكون وثيقة رسمية عُمانية أو هدفًا داخليًا معتمدًا، لكن لا يُنسب هدف داخلي إلى الوزارة.
- السجلات القديمة تبقى محفوظة كما هي؛ إذا لم يكن لها مرجع محفوظ تظهر بوصفها سجلًا سابقًا بلا مرجع موثق ولا يتم اختلاق مرجع لها.
- المعادلات الحسابية لا تتحول إلى أحكام تربوية معيارية إلا إذا كان المعيار موثقًا في المصدر المسجل.

أضيفت جداول امتداد واحد-إلى-واحد محافظة على البيانات السابقة:

```text
achievement_assessment_standards
achievement_action_metrics
```

ويضاف عقد قياس الأثر إلى مسارات التدخل الحالية عبر `PUT` و`DELETE` لمقياس الإجراء. تظهر القياسات في تفاصيل التحصيل، «يحتاج انتباهك»، التقارير الرسمية، الأرشيف، والبحث الشامل.

**v0.12.0 لا يحتاج Secret جديدًا ولا يغير Google Drive أو GitHub Workflow. ترقية SQLite تتم تلقائيًا بإضافة الجداول الجديدة فقط، ولا يلزم SQL يدوي.**

## البحث الشامل والتنقل السريع في v0.11.0

أصبح مربع **«ابحث في أعمال المادة...»** أداة تشغيل فعلية بدل عنصر بصري. يعمل البحث على السجلات الأصلية نفسها دون إنشاء فهرس موازٍ أو جدول بحث إضافي، ويدعم البيانات الحالية والتاريخية.

يشمل البحث:

- المعلمين والبيانات المهنية والسيرة الذاتية.
- الخطط ووحدات المنهج.
- التقويمات والتدخلات التحصيلية.
- الزيارات وإجراءات المتابعة الإشرافية.
- طلبات الملفات.
- الاجتماعات والقرارات.
- الفعاليات والمشاركين.
- الوثائق والمراجع.

يدعم التطبيع العربي اختلاف الهمزات والتشكيل والتطويل، ويبدأ الاستعلام بعد حرفين على الأقل. كما يمكن تصفية النتائج حسب القسم والعام الدراسي، وفتح البحث بسرعة عبر `Ctrl/Cmd + K`. نتائج الوحدات والقرارات والتدخلات وإجراءات المتابعة تشير إلى السجل الأب الصحيح حتى ينتقل المستخدم إلى موضع العمل الفعلي بدل صفحة بحث منفصلة.

مسار الخادم للقراءة فقط:

```text
GET /api/search?q=...&section=all&academicYear=all&limit=40
```

لا يفهرس البحث نصوص التقارير المولدة لأنها ناتج مشتق وليست مصدر حقيقة. **v0.11.0 لا يضيف SQL أو Secret جديدًا ولا يغير إعداد Google Drive.**

## الأرشيف التاريخي في v0.10.0

تحول تبويب **الأرشيف التاريخي** من placeholder إلى وحدة قراءة فعلية مبنية على السجلات نفسها. لا ينشئ الإصدار جدول أرشيف جديدًا ولا ينسخ البيانات؛ بل يكتشف الأعوام الدراسية من الحقول الصريحة والتواريخ التشغيلية ثم يجمع كل عام في عقد موحد.

يشمل عرض العام:

- التخطيط والمنهج.
- التحصيل والنتائج والتدخلات المفتوحة.
- الإشراف والمتابعة.
- الاجتماعات والقرارات.
- الفعاليات والأدلة.
- الوثائق والمراجع.
- طلبات الملفات.
- المعلمين المرتبطين فعليًا بسجلات العام، مع عدد الروابط لكل معلم.

مسارات الخادم الجديدة للقراءة فقط:

```text
GET /api/archive/years
GET /api/archive/year?academicYear=2026/2027
```

يقدم التبويب **حزمة تسليم قابلة للطباعة على A4**. ولأن جدول `teachers` يمثل الحالة المهنية الحالية، لا يدّعي الأرشيف أن قائمة المعلمين الحالية هي طاقم سنة قديمة؛ بل يحسب «المعلمين المرتبطين بسجلات العام» من العلاقات الموجودة في الخطط والزيارات والتقويمات والطلبات والوثائق والاجتماعات والفعاليات.

**v0.10.0 لا يضيف SQL أو Secret جديدًا ولا يغير إعداد Google Drive.**

## مركز التقارير الرسمي في v0.9.0

أصبح تبويب التقارير وحدة تشغيلية فعلية بدل placeholder. يعتمد على عقد تقرير موحد واحد ويقدم سبعة أنواع من التقارير:

- التقرير الشامل لأعمال القسم.
- التقرير المهني للمعلم.
- تقرير التخطيط ومتابعة المنهج.
- تقرير التحصيل والنتائج.
- تقرير الإشراف الفني والزيارات.
- تقرير الاجتماعات والقرارات.
- تقرير الفعاليات والتوثيق.

كل تقرير يحمل نطاق العام الدراسي والفصل، ومؤشرات محسوبة من السجلات الأصلية، وأقسامًا جدولية قابلة للطباعة على A4. مسار الخادم `/api/reports/official` للقراءة فقط ولا ينشئ جداول جديدة ولا يغير بيانات العمل. في GitHub Pages يستخدم مركز التقارير بيانات المعاينة نفسها بعقد مطابق، ولذلك يمكن فحص الشكل قبل تشغيل الخادم الفعلي.

**مبدأ مهم:** التقرير لا يعيد اختراع التحليل ولا يخلق أرقامًا موازية. فإذا كانت البيانات غير موجودة تظهر كغياب بيانات بدل ملئها بتخمينات أنيقة، وهي عادة بشرية مؤسفة في بعض التقارير.

## التحصيل والنتائج في v0.8.0

يضيف الإصدار الحالي سجلًا منظمًا للتقويمات والنتائج يتضمن:

- نوع التقويم، المادة، الصف، التاريخ، الفصل والعام الدراسي.
- المعلم المسؤول والدرجة الكلية وعدد الطلبة.
- المتوسط وأعلى وأدنى درجة.
- حد الإتقان وأعداد الطلبة في فئات: متقن، قريب من الإتقان، يحتاج تدخلًا.
- اشتقاق نسبة الإتقان ومتوسط الأداء كنسب مئوية.
- تدخلات علاجية وإثرائية ومتابعات مرتبطة بالتقويم، مع المسؤول والمدة والحالة ومؤشرات خط الأساس والهدف والنتيجة.
- اكتشاف التدخل المتأخر وإظهاره في «يحتاج انتباهك».
- سجل زمني للتقويم والتدخلات.
- مؤشر جاهزية البيانات للتحليل المتخصص.

**مهم:** لا يستنتج «مرصد الإنجازات» مهارات أو مفاهيم ضعيفة من الدرجة الكلية وحدها. التحليل التشخيصي المتقدم يبقى من اختصاص محركات متخصصة مثل **تقارير** و**بوصلة الإتقان** عند ربطها مستقبلًا، بدل إنتاج استنتاجات جميلة لغويًا وفقيرة علميًا.

## البنية التقنية

- **Frontend:** React 19 + TypeScript + Vite، بواجهة عربية RTL.
- **Backend:** FastAPI.
- **Database:** SQLite مع تفعيل Foreign Keys وWAL.
- **File storage:** تخزين محلي للتطوير، أو Google Drive عبر OAuth ونطاق `drive.file`.
- **CI/CD:** GitHub Actions لاختبار الواجهة والخادم وبناء المعاينة.
- **Live preview:** GitHub Pages في وضع معاينة آمن ببيانات نموذجية؛ عمليات الحفظ والرفع الفعلية تحتاج خادم FastAPI.

## سياسة التخزين

- Google Drive يحفظ **الملفات الفعلية** عند تفعيل الربط.
- SQLite يحفظ **البيانات الوصفية والعلاقات وحالات سير العمل**.
- مفاتيح Google لا توضع في الواجهة الأمامية.
- OAuth refresh token يحفظ مشفرًا عند إعداد `APP_ENCRYPTION_KEY`.
- روابط الرفع الخارجية تستخدم token عشوائيًا، بينما تحفظ قاعدة البيانات hash فقط.

## التشغيل المحلي

### الخادم

```bash
python -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn server.main:app --reload --port 8000
```

### الواجهة

في طرفية ثانية:

```bash
npm install
npm run dev
```

ثم افتح:

```text
http://localhost:5173
```

ولتشغيل النسخة المبنية من خلال FastAPI:

```bash
npm run build
uvicorn server.main:app --port 8000
```

إذا وجد مجلد `dist` فسيخدمه FastAPI تلقائيًا.

## Google Drive

إعداد الربط موثق بالتفصيل في [`GOOGLE_DRIVE_SETUP_AR.md`](GOOGLE_DRIVE_SETUP_AR.md). أهم متغيرات البيئة:

```text
GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET
GOOGLE_REDIRECT_URI
APP_ENCRYPTION_KEY
STORAGE_MODE
```

ولا يحتاج v0.12.0 إلى سر جديد أو SQL يدوي أو تعديل إعداد OAuth؛ الجداول الإضافية تنشأ تلقائيًا عند تشغيل الخادم.

## الاختبارات والجودة

المستودع يستخدم GitHub Actions في كل رفع إلى `main` للتحقق من:

1. تثبيت تبعيات الواجهة.
2. TypeScript + Vite build.
3. تثبيت تبعيات الخادم والاختبار.
4. اختبارات API والهجرة والتخزين.
5. بناء معاينة GitHub Pages.
6. نشر المعاينة بعد نجاح الفحوص السابقة.

تُعامل نتيجة Actions الخضراء كنقطة قبول للإصدار المرفوع، ولا يُعتمد الإصدار كمرجع مستقر لمجرد نجاح تعديل محلي.

## منهج التطوير

- **GitHub هو مصدر الحقيقة للكود.**
- التطوير يتم على مراحل صغيرة ذات نطاق واضح.
- كل مرحلة تُبنى فوق آخر نقطة استقرار خضراء.
- ترقيات SQLite إضافية ومحافظة على البيانات القديمة ما لم توجد خطة ترحيل صريحة.
- لا تُكسر العقود السابقة لإضافة وحدة جديدة.
- قبل تسليم أي حزمة تُفحص كـOverlay فوق النسخة الحالية وتُعاد اختبارات القبول من الناتج نفسه.
- المعاينة الحية تبقى قابلة للمتابعة مع كل مرحلة.

## ما هو قادم

بعد تثبيت دورة التدخل وقياس الأثر، المرحلة التالية المرشحة هي **التكامل المنضبط مع أدوات التحليل التعليمية** بحيث تستقبل المنظومة نتائج موثقة دون نسخ منطق «تقارير» أو «بوصلة الإتقان». الذكاء الاصطناعي يأتي لاحقًا بعد تثبيت عقود التكامل ومصادر الحقيقة.

## حدود المشروع

إدارة المختبرات والأجهزة والمواد الكيميائية ليست ضمن نطاق «مرصد الإنجازات». تركيز المشروع على الإدارة التربوية، المتابعة المهنية، التوثيق، التحصيل، والذاكرة المؤسسية للقسم.
